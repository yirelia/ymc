初始化系统（Initialization）

新后端细读 · NBackEnd/Modules/1_Main/NBInitialization.mo（main :82）· 平衡 NBResolveSingularities.balanceInitialization :344 · 三阶段匹配 NBCausalize.mo :262 · 运行时 simulation/solver/initialization/initialization.c

一句话抓住主线：仿真系统只回答"给定 x 算 der(x)"；但 t=0 时 x 自己也是未知的。所以后端克隆一份仿真方程，再加上 initial equation、x = $START.x、参数绑定方程，拼成第二个方程系统， 单独匹配、排序、撕裂、求解，生成到 _06inz.c。方程不够就自动补 $START，多了就删——这叫平衡。

1. 为什么需要第二个系统 — Init 模型

model Init
  parameter Real p(fixed = false)   // 参数，但不知道值——要由初始条件反算;
  Real x(start = 1, fixed = false)  // 状态，初值不固定;
  Real v(start = 0, fixed = true)   // 状态，初值固定 = 0;
  Real y;
equation
  der(x) = v;
  der(v) = -p * x;
  y = 2 * x;
initial equation
  x = 3;
  der(v) = -6;                     // 配合 x = 3 → p = 2
end Init;

仿真系统：已知 x、v、p，未知 $DER.x、$DER.v、y。3 条方程 3 个未知量，简单。 初始系统：x、v、p 也是未知的——6 个未知量（x, v, p, $DER.x, $DER.v, y），手里只有 3 条仿真方程 + 2 条初始方程 = 5 条。还差 1 条。 差的那条就是 v = $START.v——fixed = true 的意思正是"请把 start 当成一条方程"。

7. 三阶段匹配 — 初始系统专用的 Causalize NBCausalize.mo:262–306

causalizePseudoArray 里 if Partition.kindIsInitial(kind) 的分支。变量按 isFixable 分成两组，方程按 isInitial 分成两组（:268–269），然后：

阶段行方程 ↔ 变量目的
I:276–281initial equation ↔ 不可 fix 的变量用户写的初始方程优先去解那些"没法靠 start 补"的量（代数变量、状态导数）
II:284–291全部方程 ↔ 不可 fix 的变量仿真方程接着解剩下的不可 fix 量

前两阶段用 Matching.regular(…, transposed=true, partially=true)，注释（:274）明确说这两阶段不解决奇异性。设计意图：把"能 fix"的变量留到最后，让方程尽量先去解那些不能靠 $START 兜底的量。

11. 实跑 Init — 每一步在 dump 里的样子

-d=bltdump（安装版 1.25.0，--newBackend；工作区 omc 输出一致）。先看 Alias 模块的影响：y = 2x 让 x 被消掉、y 当状态，所以下面全是 y。INI 分区 Causalize 之后：

[INI] Initialization: (Causalize)
BLOCK 1: Real v        ← [SCAL] v = $START.v ($RES_SRT_6)              // 第 4 节：v 是 fixed=true → 造了 $START 方程（SRT）
BLOCK 2: Real y        ← [SCAL] 0.5 * y = 3.0 ($RES_SIM_1)             // initial equation x = 3，经 alias 变成 0.5y = 3
BLOCK 3: Real $DER.y   ← [SCAL] 0.5 * $DER.y = v ($RES_SIM_4)          // 仿真方程 der(x) = v 的克隆
BLOCK 4: Real $DER.v   ← [SCAL] $DER.v = -6.0 ($RES_SIM_0)             // initial equation der(v) = -6
BLOCK 5: parameter Real p  ← [SCAL] $DER.v = -p * (0.5 * y) ($RES_SIM_3)   // ★ 仿真方程 der(v) = -p*x 在这里解的是参数 p！

6 个未知量对 5+1 条方程，正好平衡；x 没有出现是因为它是 y 的别名。-d=initialization 会在这之前打印 "Balance Initialization / Not underdetermined."。 Solve 之后： 

[INI] Initialization: (Solve)
BLOCK 2:  y = 6.0                       (EXPLICIT)
BLOCK 5:  p = -$DER.v / (0.5 * y)       (EXPLICIT)     // 同一条方程，仿真时解 $DER.v，初始化时解 p——两个系统里因果方向不同

生成的 Init_06inz.c，五个函数按 BLT 顺序调：

void Init_functionInitialEquations_0(DATA *data, threadData_t *threadData)
{
  Init_eqFunction_5(data, threadData);   // v = $START.v   ← (realVarsData[1]).attribute.start
  Init_eqFunction_4(data, threadData);   // y = 6.0
  Init_eqFunction_3(data, threadData);   // $DER.y = 2.0 * v
  Init_eqFunction_2(data, threadData);   // $DER.v = -6.0
  Init_eqFunction_1(data, threadData);   // p = -$DER.v / (0.5 * y)   ← 写进 realParameter[0]
}

而 ODE 分区的两个块在 Solve 后标成 --- Alias of INI[1 | 3] ---：仿真方程和初始化里那份克隆解法一样，代码只生成一次。运行：The initialization finished successfully without homotopy method.
