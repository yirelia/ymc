撕裂（Tearing）与代数环

新后端细读 · NBackEnd/Modules/3_Post/NBTearing.mo（main :138 · TEARING_SET :85）· 求解 NBSolve.mo · 环的雅可比 NBJacobian.mo · 落地 NSimCode/NSimStrongComponent.mo

一句话抓住主线：撕裂 = 对一个 n 条方程互相依赖的代数环，挑 m 个"迭代变量"当未知量，其余 n−m 条方程按顺序变成显式赋值（"inner 方程"）， 剩下 m 条当"残差方程"交给牛顿法。求解器从迭代 n 维降到迭代 m 维。

新后端现状：数据结构和三段式管线都齐了，但默认方法 minimal 只把离散子系统抽成 inner 方程，连续代数环一个变量都不撕； 真正按注解撕的只有 guruTearing；每个环的雅可比算出来了却在 SimCode 侧被 if false 丢掉；所有环无论线性与否都当非线性系统生成到 _02nls.c。

1. 什么是代数环 — Loop 模型

model Loop
  Real x, y, w;
  Real z(start = 1, fixed = true);
equation
  der(z) = -z + x;
  x = 2 * y + w;         // x 要 y, w
  y = z + sin(w);        // y 要 w
  w = x * y / 5 - 1;     // w 要 x, y  → x→y→w→x 成环
end Loop;

匹配没问题（x↔第 2 条，y↔第 3 条，w↔第 4 条），但 Tarjan 排序时三条方程互相依赖、缩成一个强连通分量——没有一个"先算谁"的顺序。这就是代数环。 教科书解法：挑 w 当迭代变量，则 y = z + sin(w)、x = 2y + w 顺序可算（inner），只剩 w − (x·y/5 − 1) = 0 一条残差给牛顿法——1 维迭代，不是 3 维。

实际 dump 里环是 4×4：pre 阶段的 FunctionAlias 模块把函数调用 sin(w) 提成了辅助变量 $FUN_1 = sin(w)（方程名 $RES_AUX_4）。这个细节后面一直会出现。

所以：残差方程 = 连续方程；迭代变量 = 没被离散匹配吃掉的变量；inner = 离散子系统的 Tarjan 分量。 对一个纯连续环（Loop、LinLoop 都是），disc_eqns 为空，函数在 :429 直接跳过——这就是 dump 里 4 个迭代变量一个都没少、Inner Equations 为空的原因。 这个行为在 1.25.0 和当前 dev 版完全一致。

那"混合环"是什么样。 一个既有 Real 又有 Boolean/Integer 变量的环（比如带 if x > 0 then … else … 的关系变量 $SEV_n），minimal 会把离散变量按离散方程匹配、排序后放进 inner； 牛顿法只迭代连续变量，每次迭代顺手把离散量算一遍。这正是"mixed system"在运行时的求解方式，也是 minimal 唯一真正干的活。
