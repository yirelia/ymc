指标约简（Index Reduction）

新后端细读 · NBackEnd/Modules/1_Main/NBResolveSingularities.mo（indexReduction :67）· 触发点在 NBMatching.mo（singular :119）· 微分器 NBackEnd/Util/NBDifferentiate.mo

一句话抓住主线：指标约简 = "匹配失败的方程拿去对时间求导，直到每条方程都能配上一个未知量"，然后从多出来的状态候选里挑一些降级成"哑状态"。 新后端里它不是独立模块，是 Matching.singular 那个"匹配 → 失败 → 求导 → 再匹配"循环里的失败分支。

1. 问题是什么 — 为什么会匹配不上

后端把仿真系统看成"给定状态 x，求 $DER.x 和代数变量"。所以匹配时，状态是已知量，不参与匹配；未知量只有状态导数和代数变量。 这就出问题了：一个约束方程如果里面只有状态、没有导数也没有代数变量，它就没有任何可以匹配的未知量。 

model Index2
  Real x(start = 0);
  Real z;
equation
  der(x) = z;          // 未知量 $DER.x、z 都在，能匹配
  x = sin(time);      // x 是状态（已知），time 是已知 → 这条方程一个未知量都没有 ✗
end Index2;

两个未知量（$DER.x、z），两条方程，数量对得上，但第二条方程结构上解不出任何未知量——这叫结构奇异（structurally singular）。 数学上这是一个 index-2 的 DAE：要对约束求一次导才能显式解出所有导数。单摆（x²+y²=L²）是 index-3，要求两次。

解决办法是 Pantelides（1988）的观察：约束在所有时刻成立，所以它的时间导数也成立。x = sin(time) 求导得 $DER.x = cos(time)，这条新方程里有未知量了。 代价是：现在 3 条方程 2 个未知量，多了一条。于是必须把某个状态降级成普通代数变量（它不再由积分器积分，而是由方程算出来）——这个降级的变量叫哑状态（dummy state），它的导数叫哑导数（dummy derivative）。

5. indexReduction — 六步 NBResolveSingularities.mo:67

函数头注释（:68–104）就是算法说明书。逐步对照：

5.1 找出最小结构奇异子集 MSSS — getMSSS :450–494

不是教科书里"沿增广路径标记"，而是染色泛洪：每条没匹配上的方程（:466）分配一个新颜色，沿二分图泛洪（fillColorEqn :496 / fillColorVar :515，顺着 matching.var_to_eqn 走 :528–536）， 颜色相撞就合并（colorClustering :542）。最后按颜色分桶，每个桶就是一个 MSSS——"这一小撮方程加起来缺一个未知量"。离散方程被跳过（:486）。

changed := arrayLength(msss) <> 0（:150）。没有 MSSS 就直接返回 changed = false（:339–341），singular 不再递归。

5.2 约束方程与状态候选 — getConstraintsAndCandidates :567–603

MSSS 里的方程就是约束方程。把它们里出现的所有连续变量（不含 time、不含 dummy）收集起来作为状态候选（getStateCandidate :605–627，record 递归进子元素）。 候选数 < 约束数就直接失败（:164–168）——没东西可降级了。

三个要点：① 原方程保留，导数方程追加（:329 EqData.addTypedList(…, EqType.CONTINUOUS)、:338 EquationPointers.addList）——所以方程数增加，需要哑状态来平衡； ② 求导结果缓存在 EquationAttributes.derivative（NBEquation.mo:4089，由 Equation.setDerivative :1591 写入），同一条方程第二轮再来不会重复求导（NBDifferentiate.mo:371–373）； ③ 求导过程中顺手创造的新导数变量攒在 diffArguments.new_vars，之后过滤出 STATE_DER（:315）注册进分区（:322 :332）。

5.4 状态选择 = 一次分阶段的匹配 — :181–233

多出来的方程要靠哑状态平衡。选谁当哑状态？做法很巧：在"状态候选 ↔ 约束方程"之间再做一次匹配，匹配上的候选变成哑状态，没匹配上的留作状态。 优先级不是靠排序，而是把邻接矩阵分五个阶段逐步放开——早放进来的先被匹配、先变哑状态：

8. 实跑 ② 单摆 — 当前实现在哪里停下

model Pendulum
  parameter Real L = 1, g = 9.81;
  Real x(start = 0.5, fixed = true), y(start = -0.866);
  Real vx(start = 0, fixed = true), vy;
  Real F;
equation
  der(x) = vx;  der(y) = vy;
  der(vx) = -x * F;  der(vy) = -y * F - g;
  x^2 + y^2 = L^2;
end Pendulum;

4 个状态候选（x, y, vx, vy）、5 条方程、5 个未知量（4 个导数 + F），约束 x²+y²=L² 匹配不上 $DER.vy。教科书答案：求两次导，最终 2 个状态（比如 x 和 vx），y 和 vy 是哑状态。 工作区 omc 的实际过程（-d=dummyselect，共 6 轮）：

轮约束方程求导得到哑状态选择结果
1x²+y²=L²2x·vx + 2y·vy = 0x → 哑状态（下轮显示 [DSTA] x）；y 保留
2上一条 + 原约束2vx² + 2x·$DER.vx + 2vy² + 2y·$DER.vy = 0vx、vy 保留为状态；y 也变哑状态
31 条同上（缓存命中）x 又出现在"Selected States"里
43 条，候选里出现 [DER-] $DER.vx、$DER.vy三阶项 $DER.$DER.vx…$DER.vx 被选成状态、$DER.vy 变哑导数
5–65 条 → 8 条，候选 10 个$DER.$DER.$DER.vx…Error: NBVariable.makeDummyState failed for $DER.$DER.vx

为什么会这样。第 1 轮把 x 选成哑状态是合理的；但第 2 轮的求导方程里出现了 $DER.vx、$DER.vy， 下一轮的候选集合就把这些导数变量也当成了状态候选（它们是连续变量，满足 getStateCandidate），于是算法开始对导数变量做哑状态选择、对方程再求导，雪球越滚越大，直到 makeDummyState 遇到一个种类不是 STATE 的变量。 根源是 5.4 的阶段列表把 $DER.* 归入"3. Artificial Variables"高优先级——对 index-2 无害，对 index-3 就把导数变量当哑状态用了。 加 StateSelect.prefer/avoid 注解（PendulumSS.mo：x、vx 标 prefer，y、vy 标 avoid）在这个版本上更糟——Pantelides 无限循环， 25 分钟 CPU 打了 1.5 GB 的 dummyselect 输出，没有任何终止条件拦住它。原因同上：avoid 的变量在第 2 阶段被优先选成哑状态，第 5.4 节的分阶段匹配每轮都能"成功"， changed 永远为真，singular 就永远递归。跑它之前先想好怎么 kill。

两个版本的边界。 安装版 1.25.0 的新后端直接报 NBResolveSingularities.noIndexReduction failed——那时新后端完全没有指标约简，任何结构奇异模型都过不去； --indexReductionMethod=… 四个取值都无效（新后端不读这个 flag，Flags.mo:688 定义的选项只有旧后端用）。 工作区 1.27-dev 有了 Pantelides + 静态哑导数，index-2 能过，index-3 单摆过不去。 真要仿真单摆，现阶段用旧后端（默认）——它有动态状态选择，-d=bltdump 能看到 StateSet。
