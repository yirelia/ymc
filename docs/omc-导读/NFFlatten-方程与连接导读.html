方程前缀下推 与 连接解析

NFFlatten.mo 第二篇 · flattenEquation / flattenExp / resolveConnections

本篇讲「扁平方程表最终怎么成形」的两件事： 一是把方程里的名字统统加上前缀（v → resistor1.v）， 二是把 connect(a, b) 这种关系式，真正展开成可求解的方程。 第一件是机械下推，第二件是 flatten 里最有 Modelica 特色的一段。

Part A — 前缀下推

1. flattenEquation — 按方程种类分派 :1862

第一篇里 flattenSections（:490）对每条方程调的就是它。函数体是一个大 match eq，对每种方程种类，把里面的每个表达式都送进 flattenExp 加前缀， 然后重新装回同种类的方程。最普通的等式： 

case Equation.EQUALITY()
  e1 := flattenExp(eq.lhs, prefix, info);   // :1878 左边加前缀
  e2 := flattenExp(eq.rhs, prefix, info);   // :1879 右边加前缀
  ty := flattenType(eq.ty, prefix, info);
then
  Equation.EQUALITY(e1, e2, ty, eq.scope, eq.source) :: equations;   // :1882

其余分支都是同一个套路，差别只在「有几个表达式要下推」和「要不要额外展开」：

方程种类处理位置
EQUALITYlhs / rhs 各下推一次:1876
FORscalarize 时 unrollForLoop 整个展开；否则 splitForLoop:1884
CONNECTlhs / rhs 加前缀，但暂不展开——留给后面的 resolveConnections:1893
IFflattenIfEquation：结构条件在这里就求值，可能整支删掉:1900
WHEN逐个分支下推:1903
ASSERT / TERMINATE / REINIT / NORETCALL把各自的表达式字段下推:1909–1934
关键观察 CONNECT 在这一步只加前缀、不展开（:1893）。 connect(p, n) 里的 p、n 先变成完整名字 resistor1.p / resistor1.n， 但它还是一条 CONNECT 方程，静静躺在方程表里，等 Part B 的 resolveConnections 来收拾。 这就是为什么连接解析必须放在 flatten 主体之后——它需要看到全模型所有连接后才能建连接集。

2. flattenExp — 前缀真正下推到 cref 的地方 :1611

上面所有 flattenExp 调用最终都汇到这里。它也是一个 match exp，但真正干活的只有一个 case—— 遇到组件引用（cref）时给它套前缀： 

case Expression.CREF(cref = ComponentRef.CREF())
  exp.cref := ComponentRef.mapExpShallow(exp.cref, ...);   // :1619 先处理下标里的表达式
  exp.cref := flattenCref(exp.cref, prefix, info);      // :1620 ← 套前缀
  exp.ty   := flattenType(exp.ty, prefix, info);
then exp;

// ... 其它 case 略 ...

else Expression.mapShallow(exp, function flattenExp(prefix = prefix, info = info));   // :1636

最后那行 else（:1636）是精髓：对于加减乘除、函数调用这类复合表达式， 用 mapShallow 递归到每个子表达式，自己不用为每种运算符写一个 case。所以 R * i 会自动变成 resistor1.R * resistor1.i——不是 flattenExp 认识乘法， 而是它把前缀下推给了两个操作数，操作数是 cref 才被真正改写。

真正套前缀的一行在 flattenCref（:1685）：

cref := Prefix.apply(prefix, cref);   // :1692

而 Prefix.apply（:264）实际是 transferSubscripts——把前缀里累积的 节点路径与下标接到这个 cref 前面。至此，一个在 resistor1 作用域里写的裸名 v， 就带上了它的完整身份 resistor1.v。

另外三个特殊 case SUBSCRIPTED_EXP(split=true)（:1625）处理未标量化数组的下标替换； IF + CONDITIONAL_ARRAY（:1630）处理条件数组； INSTANCE_NAME()（:1633）把内建的 getInstanceName() 直接替换成当前前缀字符串。 主线上不必深究，知道它们是「需要特殊对待、不能只靠 mapShallow 递归」的少数派即可。

Part B — 连接解析

3. connect 的语义：先想清楚要生成什么

connect(a, b) 不是赋值，是「这两个连接器接在一起」的声明。连接器里的变量分两种， 展开规则完全不同：

变量种类物理含义展开规则例
potential（across，势变量）电压、温度、位置同一连接集里全部相等，n 个连接器给 n−1 条等式a.v = b.v
flow（through，流变量）电流、热流、力同一连接集里求和为零（基尔霍夫定律）a.i + b.i = 0
stream焓流等特殊的 inStream 加权公式见 generateStreamEquations

难点在于连接是传递的：connect(a,b) 加 connect(b,c) 意味着 a、b、c 同属一个集合， potential 变量三者全等。所以不能一条条 connect 各自处理，必须先把所有 connect 汇总成 连接集（connection sets）——本质是对「连接器」这些节点求并查集 / 连通分量。

4. resolveConnections — 六步流水线 :2433

这个函数在 flatten 主体跑完后被调用（第一篇 :388）。它把散落在方程表里的 CONNECT 方程收集、建集、生成真方程、再塞回方程表。骨架六步： 

// ① 建一张 名字 → 变量 的查找表，后面生成方程要按名字取变量属性
for v in flatModel.variables loop UnorderedMap.addNew(v.name, v, vars); end for;   // :2453

// ② 从方程表里把所有 CONNECT 收集出来（并从普通方程表里摘掉）
(flatModel, conns) := Connections.collectConnections(flatModel, ...);   // :2458

// ③ 展开可扩展连接器 expandable，再收集 flow 变量
(flatModel, conns) := ExpandableConnectors.elaborate(flatModel, conns);   // :2463
conns := Connections.collectFlows(flatModel, conns);                     // :2468

// ④ 拆分 + 标量化连接（数组连接器 a[3] 展成 a[1],a[2],a[3]）
conns := Connections.split(conns);                                       // :2482
conns := Connections.scalarize(conns, ...);                              // :2483

// ⑤ 建连接集（连通分量），再抽成一组组连接器数组
csets       := ConnectionSets.fromConnections(conns);   // :2485
csets_array := ConnectionSets.extractSets(csets);       // :2486

// ⑥ 每个连接集生成方程，追加回方程表
(conn_eql, connectedLocalIOs) := ConnectEquations.generateEquations(csets_array, vars);  // :2488
flatModel.equations := listAppend(conn_eql, flatModel.equations);                    // :2497

中间还夹着 overconstrained 连接（力学里的闭环，:2475）和 stream/cardinality 算子求值 （:2508）两段可选逻辑，初学可跳过。主干就是 收集 → 建集 → 生成 → 追加。

方程表里的 CONNECT→ Connections（收集）→ ConnectionSets（连通分量）→ generateEquations→ 真方程追加回表

5. generateEquations — 连接集怎么变成方程 NFConnectEquations.mo:86

每个连接集（一组接在一起的连接器）在这里落成方程。核心是 potential 与 flow 分开处理。

potential：全部相等，n 个给 n−1 条 :202

源码注释写得很清楚——集合 {X, Y.A, Z.B} 生成 X = Y.A 和 X = Z.B：

function generatePotentialEquations
  c1 := listHead(elements);   // 取第一个当基准
  equations := list(makeEqualityEquation(c1.name, ..., c2.name, ...)
                    for c2 in listRest(elements));   // :216 其余每个都 = 基准

（若连接的是参数级变量，生成的是 assert 相等检查而非方程，:232。）

flow：求和为零 :371

把集合里所有 flow 变量（inside 取正、outside 取负，由 makeFlowExp 定号）累加，令和为 0：

sum := Expression.fromCref(c.name);                          // :387 第一个
for e in rest loop
  sum := Expression.BINARY(sum, Operator.makeAdd(...), makeFlowExp(e));   // :392 逐个相加
end for;
equations := {Equation.EQUALITY(sum, Expression.REAL(0.0), ...)};   // :397 和 = 0

于是一句 connect(resistor1.p, capacitor1.n) 最终落成两条方程： resistor1.p.v = capacitor1.n.v（势相等）和 resistor1.p.i + capacitor1.n.i = 0（流求和为零）。这正是第一篇开头那个例子的来源。

6. 把两篇串成一张图

flatten(根类) ├─ flattenClass / flattenComponent ... ← 第一篇：树遍历产出变量 │ └─ flattenSections │ └─ flattenEquation(每条方程) ← 本篇 Part A │ ├─ EQUALITY → flattenExp(lhs/rhs) 给名字加前缀 v→resistor1.v │ │ └─ flattenCref → Prefix.apply │ └─ CONNECT → 只加前缀，不展开！留着 │ └─ resolveConnections(全模型) ← 本篇 Part B（主体之后才跑） ① collectConnections 从方程表摘出所有 CONNECT ② ConnectionSets 建连通分量（谁和谁接在一起） ③ generateEquations │ potential → a.v = b.v (n 个连接器给 n-1 条) │ flow → a.i + b.i = 0 (求和为零) └─ 追加回 flatModel.equations

两篇合起来，你就完整看懂了「一个面向对象的 Modelica 模型，如何变成一张纯变量表 + 纯方程表」。 这张扁平方程表，就是交给后端（matching / sorting / index reduction / tearing）的输入。
