OMC 编译全流程导读

总览篇 · 新前端 NFFrontEnd/ + 新后端 NBackEnd/ · 从 Demo.mo 到 Demo_res.mat · 行号来自当前工作区源码（v1.27.0-dev-372-g3ceb0c9d06），实跑输出来自工作区自编译的同版本 omc

一句话抓住主线：Modelica 编译器不是在"翻译语句"，而是在把一组方程变成一个能按时间步进求值的程序。 前端负责把面向对象的模型压平成一张变量表 + 一张方程表；后端负责把"方程组"变成"按顺序赋值"的因果化序列； 代码生成把这个序列印成 C 函数；运行时提供一个积分器循环，一步一步去调这些函数。

前端管"是什么"，后端管"怎么算"，运行时管"什么时候算"。

为什么全篇讲新后端。 仓库里有两个后端：Compiler/BackEnd/（旧，1.25 发行版默认）和 Compiler/NBackEnd/（新，--newBackend 打开）。 新后端是正在替换旧后端的重写版：数据结构重新设计、不标量化数组（for 方程整段保留）、模块顺序写死在代码里而不是靠字符串 flag 拼。 两者的思想完全一样（匹配 → 排序 → 撕裂 → 求解），但新后端代码更干净、更适合学习。本系列所有细读都基于新后端。 旧后端只需记住一个入口 BackendDAEUtil.getSolvedSystem BackEnd/BackendDAEUtil.mo:7659，读法与本文第 5 节同构。

3.3 拿 Demo 看前端的输出

本文全程用这个 8 行模型（一个一阶衰减 + 一个代数变量）：

model Demo
  parameter Real k = 2;
  Real x(start = 1, fixed = true);
  Real y;
equation
  der(x) = -k * x;
  y = 2 * x;
end Demo;

instantiateModel(Demo) 打出的 FlatModel 和源码几乎一样（2 变成 2.0，model 变成 class）——这个模型没有子组件和 connect，看不出压平的效果。换成 Modelica.Electrical.Analog.Examples.Rectifier 就会看到几百个 diode1.p.v 形式的变量，和 connect 变出来的 diode1.p.i + resistor.n.i = 0。

4. 后端 ① lower — FlatModel → BackendDAE：把变量和方程分类装箱

后端解决的核心问题只有一个：Modelica 方程是无因果的（y = 2*x 和 2*x = y 一样合法）， 但计算机只会执行赋值。后端要给每个方程指定它负责解哪个变量，再排出求解顺序。这叫因果化（causalization）。 但在因果化之前，先得知道"哪些变量是未知量"——这就是 lower 干的事。

NBackendDAE.lower NBackEnd/Classes/NBackendDAE.mo:259 只有三行： lowerVariableData（:540）→ lowerEquationData（:882）→ 组装 BackendDAE.MAIN（:111）。

4.1 变量分箱：VarData.VAR_DATA_SIM NBVariable.mo:2450

lowerVariableData 遍历每个变量，按前端标好的 varKind（NFFrontEnd/NFBackendExtension.mo:198 的 VariableKind）扔进不同的桶。 一个变量可以同时在多个桶里——桶是"视图"，底层都是指针（Pointer<Variable>）指向同一个对象：

varKind行进哪些桶意思
ALGEBRAIC:595algebraics, unknowns, initials代数变量：仿真时的未知量
STATE:601states, knowns, initials状态：仿真时是已知量（积分器给），初始化时是未知量
STATE_DER:616derivatives, unknowns, initials$DER.x：仿真时要解的量
DISCRETE:622discretes, unknowns, initials离散变量
PARAMETER:634parameters, knowns参数（不进 initials，初始化模块之后再决定）
CONSTANT:643constants, knowns

桶的完整清单在 VAR_DATA_SIM 的 23 个字段里（:2452–2483）：variables 全集、unknowns/knowns 仿真视角、initials 初始化视角、 aliasVars 被别名消掉的、derivatives/states/algebraics/discretes/parameters 按种类、state_order 状态序映射。 每个桶是一个 VariablePointers（:1949）：UnorderedMap<cref, index> + ExpandableArray<Pointer<Variable>>。

"states 在 knowns 里"这句话值得停一下。 仿真系统只回答一个问题："给定 x，der(x) 是多少"——x 是积分器喂进来的，所以是已知量；未知量是 $DER.x。 而初始化系统要在 t=0 解出 x 本身，所以 x 又在 initials 里。同一个变量在两个系统里身份不同，桶就是用来表达这种身份的。

4.2 方程分箱：EqData.EQ_DATA_SIM NBEquation.mo:4683

lowerEquationData 把 FlatModel 的四个列表变成 Equation（:1110）并起唯一名字（$RES_SIM_0 这种）， 然后 BEquation.typeList（NBackendDAE.mo:912）分箱：equations 全集、simulation、continuous、discretes、initials（只有 initial equation）、auxiliaries、removed。

Equation 的种类（:1111–1177）——注意 FOR_EQUATION，它是新后端"不标量化"的核心：

record ARRAY_EQUATION   同上 + recordSize                              :1119
record FOR_EQUATION     size, iter : Iterator, body : list<Equation>, … :1152  // for i in 1:n loop x[i] = … end for 整段保留

每条方程带 EquationAttributes（:4088）：kind（CONTINUOUS / DISCRETE / CLOCKED）、residualVar（残差变量，也代表方程本身）、derivative（对时间求过导的结果，缓存用，指标约简会用到）、exclusively_initial。

① 邻接矩阵谁依赖谁？Adjacency.Matrix.FULL（Util/NBAdjacency.mo:388）：每条方程一行，记录出现的变量集合和每个变量的可解性（Solvability :1669：EXPLICIT_LINEAR / EXPLICIT_NONLINEAR / IMPLICIT / UNSOLVABLE）。可解性靠对残差求偏导判断（:884–902）。Mapping（:96）维护标量下标 ↔ 数组下标的双向映射——这就是 pseudo-arrayNBAdjacency.mo

7. 后端 ④ Solve / Tearing / Jacobian — 把强连通分量变成可执行的东西

Causalize 之后每个分量都知道"这条方程负责解这个变量"，但方程还是 2.0 * y = x + 1 这种形式。三个 post 模块把它们变成能直接生成代码的样子：

7.1 Solve 3_Post/NBSolve.mo:92

对每个分量真的把方程解成 var = expr。核心在 solveBody（:637）： 

status := solveSimple(eqn, cref);                :663  // 先试纯结构匹配：lhs 或 rhs 恰好就是这个变量、或它的相反数

  else status := solveUnique(…);                                               :682  // 非线性但变量只出现一次 → 逐层取逆运算；否则 IMPLICIT

结果状态 Solve.Status = UNPROCESSED | EXPLICIT | IMPLICIT | UNSOLVABLE（:75）。 IMPLICIT 的单方程被 Tearing.implicit（NBTearing.mo:179）包成一个 1×1 的 ALGEBRAIC_LOOP——运行时用牛顿法解。 Solve 还维护一张 duplicate_map（:98）：ODE 分区里和 INI 分区一模一样的分量直接变 ALIAS，dump 里的 --- Alias of INI[1 | 3] --- 就是它。

7.2 Tearing 3_Post/NBTearing.mo:138

对 n 条方程的代数环，挑几个"撕裂变量"当迭代量，其余变成显式的 inner 方程，非线性求解器只迭代 m 维。 当前新后端的默认实现（minimal :403）只把离散子系统抽成 inner，连续代数环一个变量都不撕—— 这就是为什么 3 未知量的环在 dump 里迭代变量是全部 3（4）个。细读见 撕裂。

7.3 Jacobian 3_Post/NBJacobian.mo:109

两件事，同一套机器（partJacobian :1015）：每个代数环的局部雅可比 ∂残差/∂迭代变量（compJacobian :1076）， 和整个 ODE 的 A 矩阵 ∂der(x)/∂x（:1044–1073）。 做法是符号微分（Util/NBDifferentiate.mo，DifferentiationType.JACOBIAN）：造 $SEED_* 变量当微分方向，$pDER_* 变量接结果，再算稀疏模式和着色（:413）。 隐式积分器（DASSL/IDA）和牛顿法都靠它。

{

    = (-((2.0) * (((data->simulationInfo->realParameter[0] /* k PARAM */))
