这一步到底在干什么

输入是实例树（instance tree）——NFInst 阶段已经把 extends、 redeclare、修饰都展开好的、带层次结构的对象树。输出是 FlatModel（flatten 的返回值，:324），里面只有四样东西：一串 Variable、一串 Equation、初始方程、算法。

没有层次、没有类、没有继承了——resistor1.p.v 从一个「树里的路径」变成一个 「名字里带点的普通标量变量」。

flatten = 把面向对象的树，压平成一张变量表 + 一张方程表。

1. flatten — 驱动器 :320

这个函数自己不干递归，只是搭台子：

prefix := Prefix.new(classInst, ...);        // :347 空前缀，从根类开始
sections := Sections.EMPTY();                // :349 方程/算法的累加器
deleted_vars := UnorderedSet.new(...);       // :354 记录被条件删掉的变量

(vars, sections) := flattenClass(InstNode.getClass(classInst), prefix, ...);  // :356 真正的活
vars := listReverseInPlace(vars);            // :358 见下方「为什么要 reverse」

拿到结果后组装成 FLAT_MODEL（:368），然后做连接解析 （:380–391）——这是 flatten 的第二大件事，把 connect(a, b) 展开成真正的方程 （a.v = b.v，以及 flow 变量求和 a.i + b.i = 0）。这块先记住它在这儿，细节在 resolveConnections 里，不在主流程。

为什么到处 listReverseInPlace？ 因为累加变量表用的是 v :: vars （在表头插入，:748），这是 MetaModelica 里唯一 O(1) 的加法。代价是顺序反了，最后翻回来。 这是贯穿整个编译器的惯用法，看到就懂。

2. flattenClass ↔ flattenComponent — 互相递归的核心 :451 · :512

这两个函数当一对看。类含有组件，组件又是某个类的实例，所以它俩来回调，就把整棵树走完了。

flattenClass（:465 的 match）对一个类：遍历它的所有组件，逐个调 flattenComponent（:480–482）；然后处理这个类自己的方程段 flattenSections（:490）。 

case Class.INSTANCED_CLASS(elements = ClassTree.FLAT_TREE(components = comps))
  for c in comps loop
    (vars, sections) := flattenComponent(c, prefix, ...);   // 对每个组件递归
  ...
  sections := flattenSections(cls.sections, ..., prefix, ...);   // 处理本类方程

注意 TYPED_DERIVED（:494）那个 case——type Voltage = Real 这种派生类型，直接钻到基类去 flatten。

flattenComponent（:538 的 match）对一个组件，做三件判断：

步骤做什么位置
条件删除outer 组件跳过；if condition 为假的组件删掉（记进 deleted_vars）:531 :542
分类getComponentType：简单类型 / 复杂类型 / record？:550
分派见下:550–571
类型去向含义
NORMALflattenSimpleComponent :555叶子，产出一个变量
COMPLEXflattenComplexComponent :551继续往下递归
RECORD两者都做 :559record 既要展开成员，本身又作为一个变量存在

3. flattenSimpleComponent — 叶子，真正产出变量 :664

递归的终点。一个标量（或数组）变量在这里被造出来并塞进 vars。关键三行：

pre  := Prefix.push(comp_node, ty, ...);     // :727 把自己的名字接到前缀上
name := Prefix.prefix(pre);                  // :739 得到完整点号名字 a.b.c
v    := Variable.VARIABLE(name, ty, binding, visibility, comp_attr, ...);  // :740
vars := v :: vars;                           // :748 加入结果表

flattenBinding（:689）在这里把绑定值（R = 100）也带上前缀。 中间那一大坨（:695–723）是个特例：数组变量 + 有绑定 + 要 scalarize 时，把绑定改写成一条 ARRAY_EQUALITY 方程而不是留作绑定——初学可以先跳过，知道「绑定有时会变成方程」即可。

4. flattenComplexComponent — 往下钻 :920

组件本身是个复合类（比如一个 Resistor），就走这里。核心在最后 （:1013–1024）： 

pre := Prefix.push(node, ty, dims, prefix);   // :1013 名字加一层

if listEmpty(dims) then                        // 标量：直接递归回 flattenClass
  (vars, sections) := flattenClass(cls, pre, ...);      // :1017
elseif settings.scalarize then                 // 数组+要标量化：展成 a[1],a[2]...
  ... flattenArray(...)                        // :1021
else                                           // 数组+不标量化：保留数组（新后端）
  ... vectorizeArray(...)                      // :1023

看到 :1017 那行了吗——它又调回了 flattenClass。这就是互相递归闭环的地方： flattenClass → flattenComponent → flattenComplexComponent → flattenClass → … 一直到所有组件都是简单类型为止。

前面那一大段（:952–1011）处理「复杂组件带绑定」——比如 Complex c = Complex(1, 2)，得把这个 record 绑定拆到每个字段上，拆不开就变成初始方程。细节多，但不影响主干。

5. Prefix — 名字是怎么拼出来的 :150 · :192

这是理解整个 flatten 的钥匙。Prefix 就是一个 cref（component reference），随递归下降不断 push： 

function push(node, ty, dims, prefix):        // :192
  prefix.prefix := ComponentRef.prefixCref(node, ty, {}, prefix.prefix);

进 resistor1 时 push 一层 → 前缀变 resistor1；再进它内部的 p → resistor1.p；再进 p 里的 v → resistor1.p.v。到叶子时 Prefix.prefix(pre) 取出来的就是这个完整名字。下降 push，上升 pop （:216），典型的栈式前缀累加。

INDEXED_PREFIX（:156）是给数组不标量化时用的，多维护一个带下标迭代器的前缀， 初学先不管。

6. flattenSections / flattenEquations — 方程也要加前缀 :1826 · :1862

每个类自带的方程（equation 段里的），在 flattenClass 处理完组件后 （:490）统一加前缀。逻辑和变量一样：一条方程 v = R*i，在 resistor1 这层被处理时，里面的 v、R、i 全都被 flattenEquation（:1862）加上 resistor1. 前缀，变成 resistor1.v = resistor1.R * resistor1.i。

7. 把它串成一张图

flatten(根类) ← 搭台子，最后做连接解析 └─ flattenClass(类, 前缀="") ← 遍历组件 + 处理本类方程 ├─ flattenComponent(组件) ← 判断: 删除? 分类? 分派? │ ├─ flattenSimpleComponent ─────► 产出一个 Variable(叶子，名字=前缀) │ └─ flattenComplexComponent │ └─ Prefix.push(名字加一层) │ └─ flattenClass(子类, 前缀="resistor1") ← 递归回去! │ └─ ... 一直到全是简单类型 └─ flattenSections ──► flattenEquation(给方程里的名字加前缀)

主流程就这么多。剩下 3000 行是四类细节：数组的标量化/向量化 （flattenArray / vectorizeArray）、record 绑定拆分、连接解析 （resolveConnections）、以及各种绑定/表达式的前缀下推 （flattenExp / flattenBinding）。

8. 建议现在做一件事验证理解

拿个两电阻模型，亲眼看输入输出的对照：

omc -d=dumpFlatModel Model.mo

对着 dump 出来的扁平变量表，回想每个 resistor1.p.v 是走了哪条 flattenClass → flattenComplexComponent → flattenClass → flattenSimpleComponent 的路径产生的。这一对照，主流程就彻底刻进去了。
